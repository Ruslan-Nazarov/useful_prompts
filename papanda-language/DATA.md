Машинный договор: [reference/contracts.ts](reference/contracts.ts). Это определения
структуры, не готовая runtime-валидация. Каждый внешний JSON проверять до записи.
Примеры: reference/fixtures.json. Встроенные данные: reference/content/.

## Каталоги и идентичность

Word: неизменный ключ `eng` (историческое имя, не обязательный английский текст),
`word` — видимое исходное слово, `ru`, `translations: Record<code,string>`.
`source_language` для собственных слов. Пустой перевод означает отсутствие данных.
Прогресс: count, is_learned (0/1), knowledge_stats, show_stats, last_shown,
last_shown_by_lang, snoozed_until_by_lang, personal_association, is_favorite.
Новые записи используют объекты, а не JSON-строки внутри JSON.

`userWordProgress[key]` содержит пользовательские накладки: показатели,
custom_word, custom_ru, custom_translations и ai_verification.
Проекция: встроенная/пользовательская базовая запись → прогресс → правки.
Нельзя переписать immutable базу при правке карточки. Свои определения не
дублируются при каждом изменении; одна запись на ключ. При импорте повтор одного
ключа разрешается детерминированно: последняя пользовательская запись выигрывает
и заменяет совпадающую встроенную в проекции. Предпросмотр сообщает число конфликтов.

Токен: text, label, role, parts, translation, dictionary_form, dictionary_word,
is_in_my_dict, clauseIndex. `label` — часть речи/пояснение; `role` — член
предложения. `dictionary_form` — настоящая лемма данного токена; dictionary_word
— найденный ключ каталога или null. Принадлежность словарю вычисляется по текущему
каталогу, не переносится как личный факт из чужих исходников. Код `kz` стабилен
в хранилище; внешняя языковая локаль при необходимости `kk-KZ`.

Sentence: id, language (каноническая подпись English/Italiano/... из списка языков),
sentence, words в порядке чтения, source seed/manual/generated; необязательные
literalTranslation, learningGoal, markerHints, createdAt (epoch ms), generationTaskId,
generationBatchId, chainStep. В API нового агента можно использовать код языка,
но экспорт совместимости должен однозначно преобразовывать подписи.

ИИ-карточки требуют полного clauseIndex на каждом токене. Старая автономная база
может его не иметь; сохранить эвристический режим группировки, не выдавать его
за гарантированно точную разметку. parts склеиваются в text с учётом регистра.
Сопоставление поверхности допускает внешнюю пунктуацию и французскую элизию,
но не перестановку, выпадение или добавление слов. Существование морфемных частей
не доказывает их языковую правильность. Корпус содержит исторические учебные
примеры; перенос не означает, что все они прошли независимую лингвистическую экспертизу.

## Учебные записи

StructureAttempt: id, sentenceId, language, role, clauseIndex, selected[],
expected[], result correct/incorrect/disputed, hintLevel 0..2, createdAt ISO.
Не больше 500; повтор одного id обновляет запись. Спорные не входят в агрегаты.
Индекс помощи — максимальный использованный в текущем ответе, не последний.

ReadingText: id, title, language, segments[], position, cards{index:Sentence}.
1..20 непустых сегментов; каждый <=600 символов; вместе с `\n` <=6000;
до 10 текстов; позиция внутри массива. Ключ карты — десятичный индекс;
sentence и language карты совпадают с соответствующим сегментом и текстом.
Нельзя импортировать карточку для другого фрагмента или несуществующего индекса.

Дневные счётчики: ключ YYYY-MM-DD в локальном времени; счётчики — безопасные
неотрицательные целые. Событийные отметки — ISO с часовым поясом, не локальные
строки без зоны. Итог тренировки total>=correct>=0; iMW 0..100.

## Что хранится

Основное хранилище `papanda-storage`: только поля PersistedProgress из контрактов.
Встроенный словарь и предложения остаются в пакете приложения; words/sentences
восстанавливаются как производные. Загрузка: прочитать → мигрировать → проверить
→ построить проекции → открыть UI. Повреждение не должно запускать сохранение
пустого состояния поверх исходного. Есть отдельный неперсистентный ready/error.

Отдельные ключи: `papanda-onboarded`, `papanda-book-reader`,
`papanda-before-import`, идентификатор установки для прокси. Не включать сетевые
контроллеры, секреты, очереди сессии и флаги загрузки в сохраняемый прогресс.
Книжное хранилище: fontSize, bookmarks, lastLocation; проверять адреса на загрузке.
В baseline backup v1 книжные закладки и позиция, флаг введения и install ID
**не входят**. Экран экспорта должен честно объяснять это. Для полного переноса
книги добавить новый версионированный формат с миграцией, не менять молча v1.

## Резервная копия и восстановление

```json
{"app":"papanda","version":1,"exportedAt":"2026-10-21T12:00:00.000Z","data":{}}
```

`data` обязан быть валидным PersistedProgress (полный пример в fixtures.json).
Экспорт — detached deep copy, чтобы последующие правки не меняли содержимое файла.
Лимит импорта 10*1024*1024 **байт UTF-8**, а не длина JS-строки. Проверять JSON,
app, version, типы, числа, массивы, языки, уникальность ключей, связи и пределы.
Допустимые отсутствующие поля старых копий получают текущие defaults после миграции.
Неизвестная версия не импортируется. Не исполнять строки и не сливать __proto__.

Выбор файла → чтение и проверка → предпросмотр количества слов, разборов, текстов,
попыток, прогресса, конфликтов → явное «Заменить прогресс» или отмена.
До замены надёжно записать прежний прогресс в единственную локальную точку
`papanda-before-import` с savedAt. Ошибка её записи запрещает замену.
Затем отменить задания, атомарно заменить состояние, перестроить каталог,
сбросить текущие упражнения/цели и увеличить runtime revision.
Два импорта/возврата не выполняются одновременно. Успех показывать после
подтверждённой записи. Если хранилище не поддерживает транзакции, реализовать
staging/commit и восстановление незавершённой записи при запуске.

Возврат читает и проверяет точку, заменяет прогресс, отменяет фоновые задания.
Точка доступна после перезапуска и не уничтожается при возврате. Следующий импорт
заменяет её; она не является вечной историей версий. Экспорт пользователем наружу
нужен перед удалением приложения. Web использует скачивание/выбор файла,
native — системный picker/share; отсутствие share должно дать понятный результат.

## Обновления и миграции

Не переименовывать `eng` и коды языков в существующем профиле без миграции.
Миграции — чистые функции старое→новое, повторный запуск безопасен, исходный
снимок сохраняется до изменения. Legacy JSON-строки stats преобразовать в объекты,
некорректное содержимое обрабатывать предсказуемо. Миграция старого пустого ключа
в `blind` сохраняет правки, максимальные счётчики и самые поздние даты, а не
обнуляет данные; это совместимость с исходником, не правило для всех пустых слов.
Удалённые legacy sentenceReports принимать только для совместимости/миграции,
не восстанавливать по ним отсутствующий в текущем задании UI отправки жалоб.

Встроенный контент обновляется отдельно. Пользовательская правка по id имеет
приоритет над встроенной. ИИ-дубликаты сравниваются по нормализованной паре
язык+текст, не только по случайному id. Ограничение 80 ИИ-карточек не должно
оставлять середину связанной серии без начала; вытеснять целые серии или
сохранять пригодный префикс по явно проверяемой политике.
