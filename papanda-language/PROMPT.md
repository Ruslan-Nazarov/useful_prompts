# Создай papanda — приложение для изучения языков

[English](PROMPT.en.md)

Ты — разработчик мобильного приложения. Создай в текущей папке самостоятельное
локальное приложение по мотивам языкового papanda. Пиши имя `papanda` со строчной
буквы. Это языковое приложение; его комплект независим от одноимённого
приложения для тайм-менеджмента.

## Сначала прочитай

Найди каталог этого задания и полностью прочитай SPEC.md, FEATURES.md, DATA.md,
AI.md, VISUAL.md, ACCEPTANCE.md, DEPLOYMENT.md, DEVELOPMENT.md, SOURCES.md,
reference/contracts.ts, fixtures.json, design-tokens.json и manifest.json.
Изучи учебные цепочки, введение книги, общую схему и эталонные инструкции ИИ.
Проверь целостность комплекта командой `node tools/validate-kit.cjs` из его каталога.
Составь краткий план сущностей, связей, экранов, этапов и проверок. Затем пиши код.

Если документы задают разные аспекты одной функции, выполни их вместе:
SPEC — поведение; DATA — формат и инварианты; AI — запросы и доверие;
VISUAL — оформление; FEATURES/ACCEPTANCE — полнота и проверки.
Если обнаружишь реальное противоречие, зафиксируй решение и его последствия.
Не заменяй подробное задание общим списком «словарь, карточки, ИИ».

## Главная мысль приложения

Ученик узнаёт, как слова выражают целую мысль. Начинай с целого предложения,
находи всё сказуемое, затем подлежащее и добавления. Не заставляй сначала выучить
все слова. Не путай члены предложения с частями речи. Составное сказуемое может
включать несколько разделённых слов, а подлежащее может быть не выражено явно.
Сохраняй собственную грамматику каждого языка.

## Обязательные части

1. Вводные экраны: метод, роли, словарь и повторение; пропуск, завершение,
   повтор из настроек. Дождись безопасной загрузки прогресса до открытия занятий.
2. Пять вкладок: статистика, слова, разбор предложений в центре, узнавание слов,
   настройки. Словарь, мастерская и книга открываются поверх с понятным возвратом.
3. Семь языков практики: en, it, es, de, fr, kz, la. Выбор и порядок активных
   языков сохраняются; нельзя убрать последний язык. Русский — язык пояснений
   и отдельный раздел книги, но не восьмой тренажёр.
4. Слова: одна мысль/слово рядом на активных языках, конечные туры, приоритет
   слабой памяти, избранное, ассоциация, редактирование, отмена отметки,
   переход от конкретного перевода к предложению с этим словом.
5. Словарь: поиск по всем переводам и ассоциациям, добавление и изменение слова,
   неизменный ключ хранения, статистика по языкам, проверка перевода через ИИ.
6. Узнавание: скрытый ответ, «Знаю/Не знаю», свайпы, отмена, отложить на 7 дней,
   лимит сессии, доля знакомых слов, избранное и отдельный план повторения сегодня.
   Алгоритмы очереди и iMW реализуй буквально по SPEC.md.
7. Разбор: исходный порядок слов при раскрытии групп по грамматическим основам
   и ролям; пошаговый/полный показ; перевод; морфемы; связь со словарём; очереди;
   добавление и редактирование карточки с проверкой соответствия текста и токенов.
8. Мастерская: самостоятельный выбор слов каждой роли, подсказки и наблюдаемые
   маркеры, спорные ответы, нарастающие серии, развитие своей мысли, сопоставление
   одной мысли на семи языках, следующий пример по слабой роли.
9. Свои тексты: проверяемое деление на предложения, явное подтверждение границ,
   чтение по одному, разбор через ИИ по кнопке, сохранение позиции и карточек.
10. Книга: все 66 материалов из комплекта без сети, поиск, оглавление, ссылки
    на точный фрагмент, карточки и таблицы, шрифт, закладки, продолжение чтения;
    переход правило ↔ упражнение с учётом помощи. У латыни нет отдельной главы.
11. ИИ: собственный серверный прокси; составление → разметка → локальная проверка
    → независимый аудит → ограниченное исправление. Объяснение с реальными
    отрывками книги, основа сначала, слова/окончания отдельно; краткое/подробное
    объяснение произношения. Показывай этапы, отмену и ошибки. Поздний ответ после
    смены карточки/языка/импорта не должен менять новое состояние.
12. Данные: локальный прогресс отдельно от встроенного контента; резервная копия
    с предпросмотром, проверкой и точкой возврата; безопасный сброс статистики.
    Не включай в новый профиль показатели исходного автора.

## Реализация

Базовая совместимая линия исходника: Expo SDK 54, React Native 0.81.5,
React 19.1, TypeScript, React Navigation, Zustand, AsyncStorage; Cloudflare Worker
с SQLite Durable Object для квот. Это снимок исходной реализации, не утверждение
о последней доступной версии. Можешь выбрать поддерживаемую совместимую линию,
обосновав выбор и проверив API по официальной документации. Не смешивай зависимости
разных SDK. Создай настоящий Android-проект, web для удобной проверки и код для iOS.

Раздели интерфейс, чистые учебные алгоритмы, каталог, пользовательский прогресс,
контент книги, транспорт ИИ и серверные адаптеры. Зафиксируй зависимости lock-файлом.
Поставляемые контракты и данные — входные материалы, не готовая архитектура приложения.
Не копируй исторические патчи зависимостей без проверки применимости.

ИИ не требуется для запуска, автономных примеров, встроенных цепочек и книги.
При неподключённом сервисе объясни недоступность сетевой функции, сохрани упражнение.
Ключи провайдеров хранятся только на сервере. Не используй адреса, идентификаторы
проектов, учётные записи, подписи и секреты исходного автора. EXPO_PUBLIC-переменные
попадают в клиент. Собственный текст ученика передаётся провайдеру только при
запуске соответствующей функции; автоматическое пополнение примеров опиши явно.

## Порядок доведения до результата

1. Рабочая автономная вертикаль: загрузка → язык → предложение → словарь →
   ответ → перезапуск с сохранёнными данными.
2. Все учебные режимы, статистика, редакторы и настройки; затем книга и её связи.
3. Экспорт, предпросмотр, импорт, возврат, миграции и отказоустойчивость.
4. Прокси и ИИ-протокол с заглушками; затем отдельно проверка реального сервиса,
   если предоставлены собственные настройки.
5. Интерфейс по VISUAL.md, автоматические проверки и все сценарии приёмки.
6. Инструкции запуска/разработки/развёртывания, .env.example, CI, отчёт готовности.

Этапы не являются разрешением остановиться после минимального прототипа.
Не выдавай план за выполнение. Проверяй поведение, а не наличие названий кнопок.
Сетевые аккаунты и аппаратные ограничения обозначай точно; продолжай независимую
работу. Не подменяй реальную проверку APK экспортом JavaScript.
