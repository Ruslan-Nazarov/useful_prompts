# Протокол ИИ и доверие к результату

[English](AI.en.md)

Эталонные полные инструкции: `reference/ai-prompts/*.ts.txt`. Это исходные
шаблоны с TypeScript-интерполяциями, а не готовые runtime-модули. Реализуй
построители с теми же входами; не отправляй буквальные `${...}` провайдеру.
AI_SYSTEM_PROMPT, AI_PRONUNCIATION_PROMPT и подробный вариант описывают подачу;
sentencePrompts — составление/разметку и особенности языков; sentenceQuality —
независимый аудит; sentenceCurriculum — план заданий. Спецификации этого комплекта
определяют продуктовый договор при различии со старым комментарием исходника.

## Транспорт

Клиент знает только `EXPO_PUBLIC_GEMINI_PROXY_URL`, полный URL `/v1/generate`.
Пустое значение — автономный режим. URL не является секретом.

```http
POST /v1/generate
Content-Type: application/json
X-Install-Id: <локально сохранённый идентификатор установки>
```

```json
{"prompt":"...","provider":"gemini","generationConfig":{"temperature":0.2,"maxOutputTokens":4096,"responseMimeType":"application/json","responseJsonSchema":{"type":"object"}}}
```

provider необязателен: gemini/cerebras/groq. Успех HTTP 200 `{"text":"..."}`,
не готовый доверенный JSON карточки. Ошибка: error (безопасный текст), code,
retryable и при исчерпании дневной квоты daily. 400/413 для неверного запроса/размера,
429 для квоты, 502/504 для сбоя/таймаута провайдера; CORS preflight OPTIONS.
`GET /health` возвращает состояние без ключей. Не отдавать сырой ответ с секретом.

Пределы: тело 256000 байт, в том числе chunked; prompt 1..60000 символов;
temperature 0..2, topP 0..1, maxOutputTokens 1..16384;
thinkingBudget 0..8192, includeThoughts boolean. responseJsonSchema — объект,
responseMimeType — application/json. Неверный provider отклонить.
Для Gemini использовать нативные параметры; для Cerebras/Groq — chat-completions
адаптер с инструкцией схемы и JSON-object mode. Если API требует объект, оборачивать
массив в документированный `{items:[...]}` и нормализовать на границе адаптера;
не требовать одновременно несовместимые top-level array и object mode.

Ключи GEMINI_API_KEY/CEREBRAS_API_KEY/GROQ_API_KEY — только Worker secrets.
DEFAULT_PROVIDER и имена моделей — серверная конфигурация. Выбирать доступные
модели перед развёртыванием по документации провайдера; модель из старого снимка
не является обещанием доступности. Fallback — не более второго провайдера на
один допущенный запрос, только если он настроен. Таймаут попытки провайдера 20 с,
клиентской попытки 45 с. Клиент — максимум 4 попытки с отменяемыми паузами
min(1500*2^(attempt-1),10000) мс. daily/retryable=false/обычные 4xx не повторять;
временные сетевые ошибки, 408 и разрешённые 429 повторять ограниченно.

## Квоты

SQLite Durable Object, binding QUOTA, класс QuotaLimiter, миграция v1-quota.
Приём запроса атомарно резервирует per-install hourly/daily и global daily.
Исходные настраиваемые пределы: 40/час, 200/день на установку, 1500/день глобально.
Одновременные запросы не могут обойти глобальный предел. Отклонённый запрос не
тратит глобальную квоту; допущенный считается один раз, даже с fallback.
Счётчик измеряет клиентские запросы, не токены и не все вызовы провайдера.
Границы окон квоты — серверные UTC hour/day; UI не смешивает их с локальным учебным днём.
X-Install-Id контролируется клиентом и не является аутентификацией; CORS тоже
не ограничивает доступ. Глобальный бюджет обязателен. Не добавлять «секретный»
пароль в публичный клиент как имитацию аутентификации.

## Составление и проверка карточек

Обычная партия — 8 заданий, допустимый запрос 1..20. Цикл:
core, attribute, object, circumstance, negative, reading, question, complex.
Первые четыре при достаточном размере — одна развивающаяся мысль; цепочка
планируется от естественной полной фразы с допустимым дополнением назад к основе.
Для конкретного слова первое задание usage: слово/выражение обязано употребляться
естественно, допускаются подходящие отрицание/вопрос/сложность, остальные задания
не развивают usage. Словарь помогает найти леммы, не ограничивает сцену случайным
набором слов и не определяет уровень владения грамматикой.

1. **COMPOSE_SENTENCES**: задачи с id, focus, goal, develops; прошлые принятые
   примеры, избегаемые тексты, нужное слово и замечания. Ответ — taskId+sentence,
   без разметки. Не принимать лишние/повторные/чужие taskId, пустой текст, >600 символов.
2. **REVIEW_AND_ANNOTATE**: исходные тексты, задачи, особенности языка и реальные
   отрывки книги. Ответ — тот же текст, taskId, review natural/taskFit/
   analysisReliable=true, цельный русский перевод и words. На этом этапе текст
   не переписывается; сомнительный пример отклоняется.
3. **Локальная проверка**: схема, язык, неизменность текста, покрытие поверхности,
   роли/индексы, словарные формы, parts, отсутствие дубликата, наличие нужной
   лексемы, соответствие focus, сохранение основы цепочки и порядок taskId.
   Обрабатывать большие каталоги порциями с уступкой UI; отмена доступна во время
   проверки. Схема не доказывает семантическую или языковую правильность.
4. **AUDIT_SENTENCE_CARDS**: отдельный вызов видит готовые карточки, соседей и задачи,
   но не уверения модели-аннотатора. По каждой — taskId, natural, translation,
   roles, morphology, chain и reason. Принимается ровно один полный вердикт,
   все пять boolean=true. Пропущенный/дублированный/неполный вердикт — отказ.
5. **Исправление**: не более двух раундов всего (первый + один ремонт) с конкретными
   замечаниями. Если часть цепочки не прошла, пересоставить цепочку целиком,
   не склеивать две сцены. Не заменить более длинный проверенный префикс коротким
   неудачным ремонтом. Принятые независимые примеры сохранить; качество важнее
   заполнения всех 8 мест. Целевой запрос без task-1 с нужной лексемой не успешен.

Проверяемые языковые ловушки: составное/разделённое сказуемое; отрицание внутри
сказуемого; именное сказуемое; нулевое подлежащее; passive Subject; не каждый
предлог — Object; согласование; французская элизия; немецкая рамка; казахское
дополнение без падежного окончания и аналитическое отрицание; латинские падежи.
Не переводить артикль как «этот/один», вспомогательное do как «делает»,
Қыз ұйықтаған жоқ как «девочка спавшая нет». Цельный перевод — грамматический
русский с тем же смыслом, временем и отрицанием, не механическая склейка глосс.

## Объяснение и книга

Передать точную фразу, перевод, текущие токены, роли, индексы, леммы, морфемы.
Из локальной книги выбрать ограниченный контекст (до 11000 символов): метод,
общая схема, главы нужного языка/роли, лексические/морфологические совпадения.
Каждый отрывок имеет существующий chapterId/blockId и book://-адрес.
Не выдумывать латинскую главу: дать общий метод с явной пометкой.

Ответ по-русски, понятно и спокойно: сначала конкретная фраза, всё сказуемое,
потом подлежащее и значимые добавления, наблюдаемые признаки. Без обязательной
похвалы, отвлечённого заключения и паспорта каждого слова в главном тексте.
Отдельный сворачиваемый слой «Разобрать слова и окончания» даёт подробности
всех слов/служебных элементов. Старый неразделённый ответ остаётся читаемым.
Не более двух книжных ссылок во всём ответе; список реальных переданных источников
свёрнут и доступен отдельно. Ответ явно обозначен как пояснение ИИ.

Проверка ссылок — по whitelist именно переданных адресов. Выдуманная ссылка,
слишком много ссылок, HTML, таблица или непереведённые термины вызывают один
ремонт с предыдущим ответом и конкретными замечаниями. Затем неподтверждённые
ссылки удалить; не приписывать собственное объяснение автору книги. Источники
показывать даже если модель нарушила разметку слоёв. Внешние ссылки не исполнять
как код. Проверка существования ссылки не проверяет верность применённого правила.

Произношение: кратко — русская запись с ударением и максимум две подсказки,
до 60 слов; подробный вариант отдельно. Кеш раздельный для режимов и точной
пары слово+язык. Закрытие/смена карточки отменяет запрос; повтор после ошибки.

## Конкурентность, фон и приватность

Каждое задание имеет AbortSignal и revision контекста: язык, режим, карточка,
содержание/разметка, позиция текста. Проверять revision перед каждым commit.
Закрытие окна, смена карточки/языка, удаление текста, очистка кеша, импорт и сброс
делают старый ответ недействительным. Совпадающие фоновые запросы можно объединять;
явное целевое действие имеет собственный транспорт и приоритет. Не блокировать
пять вкладок, карточки и отмену. Кеш объяснения учитывает текст/разметку/раскрытия,
а не только прежний id.

Автопополнение при подключённом сервисе: один процесс, проверки не чаще 25 с,
порог менее 6 ИИ-примеров активного языка, партия 8; языки последовательно,
пауза 2 с между ними, ошибки не разрушают автономную очередь. Объяснить фоновые
запросы и ограничить их жизненным циклом активного приложения; не загружать туда
читательские тексты, ассоциации и весь прогресс. Свой текст отправляется только
при запуске его разбора. Политика приватности описывает фактические поля запросов.
Локальная отмена прекращает ожидание и запись; уже отправленный текст отозвать
нельзя, возврат квоты или остановка серверной генерации не гарантируются.
