## Структура создаваемого проекта

```text
App.tsx                 запуск, hydration, onboarding, стек и вкладки
src/models/             типы предметной области
src/constants/          языки, роли, визуальные токены
src/data/               неизменные учебные каталоги и compiled book
src/store/              persisted types, defaults, validation, migration, projections
src/utils/              чистые алгоритмы очередей, iMW, группировки и сравнения
src/services/           AI transport, pipeline, book lookup, backup/restore
src/hooks/              жизненный цикл отменяемых задач и редакторов
src/components/         токены, упражнение, книга, редакторы, окна
src/screens/            экраны из SPEC
book/                   исходные материалы с исходной лицензией
scripts/                генератор книги и UI harness
tests/                  unit/integration/regression
gemini-proxy/src/        HTTP, валидация, адаптеры, Durable Object
gemini-proxy/tests/      upstream mocks и конкурентность квот
docs/                   решения, развитие, восстановление, релиз, приватность
```

Можно выбрать другую организацию при сохранении этих границ. UI не содержит
единственную реализацию iMW, выбора очереди или проверки данных. Каталог
производен от базы и накладок; один и тот же projector используется после
правки, импорта, отмены и перезапуска. Компоненты подписываются на нужные поля,
а не перерисовывают всю базу при каждом нажатии.

## Команды и CI

Агент реализует npm scripts: book:build (детерминированный compile), book:check
(проверка свежести без записи), type-check (app), type-check:proxy, test
(unit/integration обоих проектов), check (все предыдущие проверки без сборки
релиза), check:ui (все UI-сценарии одной web-сборки). Worker build — dry-run.

CI с Node.js 22+: npm ci, npm ci --prefix gemini-proxy, npm run check,
экспорт web с фиктивным URL, npm run check:ui, dry-run Worker. Сохранять
краткие логи и скриншоты ошибок, не реальные профили/секреты. Установка после
клонирования воспроизводится lock-файлами. Версии закрепляются и обновляются
совместимыми группами Expo/React Native/React; не копировать исходные overrides
и postinstall-патчи без воспроизведения конкретной проблемы.

Автоматически проверять:

- Формулу iMW, нулевые/испорченные stats, выборку очереди с фиксированной
  случайностью, локальные дни, due/snooze, undo без отката независимых правок.
- Группировку нескольких основ, разорванное сказуемое, помощь/спорные ответы,
  добавленные повторяющиеся слова, целостность развивающейся мысли.
- Все границы JSON, UTF-8 размер backup, конфликты ключей, повреждённый storage,
  отказ записи restore point, сохранение/возврат после перезапуска.
- AI malformed JSON, пропуски/дубликаты taskId, неверные parts/переводы, отсутствие
  нужной лексемы, сомнительный аудит, один ограниченный ремонт, отмена fetch/паузы,
  поздние ответы после смены контекста, приоритет явной задачи.
- Источники книги, checksum, ID, поиск, адреса, таблицы, bookmarks/position,
  языковые ограничения ru/la, цитаты только из переданного контекста.
- Worker body/config validation, fallback/timeout, ответы без секретов,
  атомарность глобального/per-install бюджета при конкурентных запросах.

UI-сценарии: вводные экраны, обычная навигация, мастерская/тексты, книга,
повторение, разбор/редактор, управление генерацией, ввод/правка слов и туры слов.
Один статический экспорт, отдельный чистый профиль браузера для каждого сценария.
Состояния сетевых этапов задерживать контролируемо; внешнюю сеть блокировать.
Проверить 320/390/768/1440 и замедленный CPU. Реальный APK, системные picker/share,
нативная клавиатура и реальное качество ИИ проверяются отдельным прогоном.

## Изменение словаря и примеров

Начальный каталог берётся из reference/content/words.json с нулевыми счётчиками.
Не переносить историю автора из другой базы. Статические примеры и authored
цепочки не являются пользовательскими записями. Новое упражнение проверяется
по грамматике языка, роли/части речи, surface/parts, смыслу, переводу и лемме.
Если деление неизвестно — одно целое слово. Сначала простая полная фраза, затем
детали; не менять глагол «спит» на «читает», выдавая это за добавление дополнения.
Хранить происхождение и уровень проверки контента; автоматический pass не
объявлять лингвистической экспертизой. Собственные изменения учебного контента
не должны ломать идентичность старого прогресса.

## Книга: воспроизводимый compile

В комплекте исходные 66 Markdown и reference/book/catalog.json. Для первого
запуска можно использовать готовый каталог, но агент обязан реализовать
генератор и fresh-check по собственным исходникам. Сохранить sourcePath/sourceHash
и соответствие глав/блоков, а не создавать книгу из пересказа ИИ.
Полный алгоритм исходного генератора приложен как
reference/book/build-book.cjs.txt; он требует markdown-it/entities и предполагает
проектные пути. Это эталон для адаптации, не команда готового приложения.

Новый compile: UTF-8 источники → headings/text/tables с rowSpan/colSpan →
стабильные chapterId/blockId → SHA-256 исходников → JSON. Для sourceHash сначала
нормализовать CRLF в LF, как в исходном генераторе; manifest.sha256 проверяет
сырые байты файлов отдельно. Для сгенерированного JSON закрепить LF через
reference/config/gitattributes.example или нормализовать сравнение: исходный
строгий --check иначе может ошибочно считать CRLF-копию устаревшей на Windows.
Одинаковые входы
дают одинаковый результат. book:check компилирует в память и сравнивает.
Изменённый блок может получить новый id; устаревшие bookmarks фильтруются.
Не включать аналитику, HTML-скрипты и материалы съёмки из исходного сайта.
Исходные docx не нужны для сборки комплекта и не изменяются.

## Данные и асинхронность

Сначала валидировать весь объект, потом commit. Restore point пишется до импорта,
успех — после завершённого сохранения. При отсутствии транзакций хранить staging
и восстанавливаться из него. Любое замещение прогресса увеличивает revision и
отменяет текущие задания; старые callback не должны записать новую подборку в
прежний профиль. Undo восстанавливает затронутые поля, не весь старый объект.
Никакая миграция не запускает очистку живого профиля при ошибке.

## Документация и выпуск

README: требования, точные команды, автономный/сетевой режимы, env, расположение
данных, backup, известные ограничения. docs/architecture.md: владельцы состояния
и потоки. docs/content.md: книга/каталог и лицензии. docs/privacy.md: реальные
передаваемые данные, фоновые запросы, провайдеры, отсутствие облачного backup.
docs/release.md: SDK, версия/versionCode, среда, checks, проверенные устройства,
артефакт/SHA-256 и ограничения. docs/decisions.md фиксирует решения отклонений.

В отчёте готовности — каждый F-ID и A-ID, реализация и фактически выполненная
проверка. Статусы `не проверено` и `блокировано` не подменять словом `готово`.
Инструкция по deployment не равна публикации. Для запроса аккаунта/ключа сначала
довести автономное приложение и все независимые проверки до обозримого результата.
Не включать аккаунты, подписи, EAS projectId, рабочий URL/ключи автора в новый проект.
