# Техническое задание: настольный конвертер документов convert

[English](SPEC.en.md)

Реализуйте автономное локальное desktop-приложение для Windows по этому заданию, [FEATURES.md](FEATURES.md) и [VISUAL.md](VISUAL.md). Приложение предназначено для конвертации между форматами PDF, DjVu, DOCX, FB2, EPUB, а также для автономной работы со страницами и оптимизацией PDF.
Название приложения всегда пишется со строчной буквы — `convert`.

---

## 1. Общие принципы и архитектура

1. **100% Оффлайн и независимость от внешнего софта**:
   - Приложение работает полностью локально без доступа в интернет.
   - Конвертация `DOCX → PDF` и `PDF → DOCX` выполняется без установленного Microsoft Office, Word или LibreOffice с использованием легковесных библиотек (`python-docx`, `ReportLab`, `pdf2docx`, `PyMuPDF`).
2. **Изоляция ресурсоёмких конверсий**:
   - Преобразования `PDF → DOCX` и `DOCX → PDF` запускаются в изолированном дочернем процессе-воркере (`--worker`), чтобы аварии или утечки C-библиотек не приводили к падению графического интерфейса.
   - Межпроцессная отмена контролируется через сигнальный файл отмены (`cancel_file`), проверяемый на каждом этапе рендеринга.
3. **Атомарность публикации файлов (Safe Write)**:
   - Все промежуточные файлы формируются во временной папке.
   - Публикация готового файла атомарна. Ошибки или отмена пользователем не оставляют повреждённых или неполных файлов в целевой папке.
   - Поддерживается кросс-дисковое перемещение (Cross-Volume Move, Windows `WinError 17`): если временный каталог и папка назначения находятся на разных логических томах, запись выполняется через промежуточный staging-файл в папке назначения с последующей атомарной заменой.
   - Защита от непреднамеренной перезаписи: если файл с таким именем уже существует и перезапись не запрошена, создаются суффиксы `_2`, `_3` и т. д.
4. **Многопоточность и отзывчивость**:
   - Ни одна длительная операция (анализ, конвертация, склейка, сжатие) не блокирует главный UI-поток. Все задачи выполняются через пул потоков `QThreadPool` / `QRunnable` с передачей сигналов прогресса.

## 2. Поддерживаемые направления конвертации

| Направление | Инструмент реализации | Особенности поведения |
|---|---|---|
| **DjVu → PDF** | Утилита `ddjvu` | Страницы экспортируются как растровые изображения с сохранением исходного DPI. Текстовый слой не переносится. |
| **PDF → DjVu** | Утилита `pdf2djvu` (с резервом `c44` + `djvm`) | Перенос доступного текстового слоя, гиперссылок и оглавления. При сбое нативного `pdf2djvu` автоматически срабатывает резервный алгоритм покадрового сжатия через `c44` и сборки через `djvm`. |
| **PDF → DOCX** | `pdf2docx` + `PyMuPDF` | Реконструкция текста, колонок, таблиц и встроенных картинок. Сканированные документы остаются изображениями (без OCR). |
| **DOCX → PDF** | `python-docx` + `ReportLab` | Автономный экспорт структуры: абзацы, стили, таблицы, разрывы страниц, встроенные иллюстрации, системные шрифты Windows (Segoe UI, Arial, Times New Roman). Сложные диаграммы предупреждают пользователя. |
| **FB2 → DOCX** | `xml.etree.ElementTree` + `python-docx` | Извлечение глав, подзаголовков, абзацев, сносок и раскодирование `base64` иллюстраций из книги. |
| **FB2 → PDF** | Двухэтапный экспорт (`FB2 → DOCX → PDF`) | Полная книга FB2 в форматированный документ с оглавлением. |
| **EPUB → DOCX** | `zipfile` + разбор `content.opf` / spine + `python-docx` | Извлечение последовательности глав по манифесту OPF, очистка HTML-разметки и перенос изображений. |
| **EPUB → PDF** | Двухэтапный экспорт (`EPUB → DOCX → PDF`) | Готовый PDF с сохранением иерархии глав и обложки. |

## 3. Набор инструментов PDF (PDF Tools)

Все инструменты реализованы на базе высокопроизводительной библиотеки `PyMuPDF` (`fitz`):

1. **Склейка PDF (Merge)**:
   - Объединение двух и более PDF документов в один файл.
   - Сохранение и склейка дерева закладок/оглавления каждого файла.
   - Финальная дефляция и очистка неиспользуемых объектов (`garbage=4`, `deflate=True`).
2. **Разделение PDF (Split)**:
   - Режим постраничного разбиения: сохранение каждой страницы в отдельный файл `{stem}_стр_001.pdf`.
   - Режим диапазона страниц: парсинг выражений вида `1-3, 5, 8-12` с валидацией границ и удалением дубликатов.
3. **Фотографии в PDF (Images to PDF)**:
   - Конвертация набора изображений (JPG, PNG, WEBP, BMP, TIFF).
   - Выбор размера страницы: «Исходный размер картинки», «A4 книжная» (595 × 842 pt), «A4 альбомная» (842 × 595 pt).
   - Сохранение пропорций изображения (`keep_proportion=True`).
4. **Сжатие и оптимизация PDF (Compress)**:
   - Профили сжатия: «Компактное» (144 DPI, JPEG quality 65), «Сбалансированное» (200 DPI, JPEG quality 80), «Высокое» (300 DPI, JPEG quality 90).
   - Безопасная оптимизация растровых XObject: если картинка сжимается более чем на 12%, заменяется поток и обязательно обновляется заголовок объекта (`/Filter /DCTDecode`, `/ColorSpace /DeviceRGB`), а `/DecodeParms` обнуляется.
   - Изображения с альфа-каналами и масками прозрачности (`SMask`) не повреждаются и пропускаются при JPEG-рекомпрессии.
   - Глубокая очистка неиспользуемых шрифтов и потоков через параметры сохранения PyMuPDF.

## 4. Хранилище статистики и телеметрия

1. **База данных SQLite**:
   - Файл базы данных размещается в `%LOCALAPPDATA%\ConvertApp\stats.db` (или `~/.convertapp/stats.db` на не-Windows системах).
   - Таблица `meta`: хранение количества запусков (`launch_count`), меток первого и последнего запусков.
   - Таблица `operations`:
     - `id`: автоинкремент первичного ключа;
     - `session_id`: идентификатор сессии вида `sess_{timestamp}_{pid}`;
     - `operation`: тип действия (`convert`, `merge`, `split`, `images_to_pdf`, `compress`);
     - `source_format`, `target_format`: строковые расширения;
     - `source_size`, `target_size`: размеры в байтах;
     - `duration_sec`: время выполнения в секундах;
     - `status`: статус (`success`, `error`, `cancelled`);
     - `error_message`: текст ошибки при сбое;
     - `timestamp`: точное время эпохи UNIX.
2. **Интеграция с лаунчером Albert**:
   - Аргумент командной строки `--stats`: мгновенный вывод полного JSON-отчёта метрик в `stdout` с выходом `0`.
   - Аргумент `--albert-report <path>`: автоматическая синхронизация сводки по указанному пути.
   - Автоматическая синхронизация файла отчёта в `%LOCALAPPDATA%\ConvertApp\albert_telemetry.json`.
3. **Мост телеметрии ProcessDock**:
   - При наличии папки `.bridge/telemetry` в родительском каталоге или переменной окружения `ALBERT_BRIDGE_DIR` каждое действие формирует атомарный JSON-файл события с уникальным UUID.

## 5. Интеграция с проводником Windows (Shell Context Menu)

- Интеграция регистрируется в ветке текущего пользователя `HKEY_CURRENT_USER\Software\Classes` и не требует прав Администратора (UAC).
- Для документов (`.pdf`, `.djvu`, `.djv`, `.docx`, `.fb2`, `.epub`):
  `HKCU\Software\Classes\SystemFileAssociations\{ext}\shell\ConvertApp` со строкой «Конвертировать документ (Convert)».
- Для изображений (`.jpg`, `.jpeg`, `.png`, `.webp`, `.bmp`, `.tiff`):
  строка «Создать PDF из фото (Convert)».
- Команда запуска корректно передаёт параметр `"%1"` в скомпилированный EXE либо в `pythonw app.py`.
- Удаление интеграции чисто рекурсивно вычищает только зарегистрированные ключи приложения.

## 6. Требования к сборке и портативности

- Поддержка упаковки через PyInstaller в единую портативную папку `dist/Convert` с вложенным каталогом `_internal`.
- Встроенные бинарные утилиты `ddjvu`, `pdf2djvu`, `c44`, `djvm` и сопутствующие библиотеки располагаются в каталоге `tools/` внутри пакета приложения.
- Скрипт сборки включает этап верификации: тестовая конвертация `PDF → DjVu → PDF` через собранный `.exe` с флагом `--self-check` перед заменой рабочей версии.
