# Правила публичного репозитория / Public repository rules

- Позиционирование: `papanda — приложение для тайм-менеджмента`; по-английски `papanda — a time management app`.
- Product description: `papanda — a time management app`.

- Название приложения всегда пишется `papanda`, со строчной буквы, в том числе в начале предложений и заголовках. Технические имена переменных, классов и API сохраняют совместимость.
- Публичные материалы адресованы читателю, который собирает своё приложение. Не добавляйте сценарии съёмки, обращения к автору видео, внутренние ревью, служебные инструкции публикации и локальные скрипты подготовки ролика.
- Не публикуйте личные базы, `.env`, ключи, токены, локальные пути или снимки приложения. Примеры данных должны быть явно вымышленными.
- Поддерживайте русскую и английскую версии промптов, README и требований. Пример данных остаётся на русском.
- Описание возможностей и визуальные требования — часть публичного задания. Не удаляйте полезный каталог функций целиком из-за съёмочных заметок: очищайте только внутренние разделы, сохраняя полный материал автора локально.

- Spell the application name `papanda`, always lowercase, including sentence openings and headings. Preserve compatibility of technical identifiers and APIs.
- Address public materials to readers building their own app. Keep filming scripts, video-author instructions, internal reviews, publication procedures, and local recording helpers outside this repository.
- Never publish personal databases, `.env` files, keys, tokens, local paths, or application snapshots. Clearly mark sample data as fictional.
- Maintain Russian and English versions of prompts, READMEs, and specifications. The sample fixture remains in Russian.
- Feature descriptions and visual requirements belong in the public assignment. Remove internal filming sections without deleting useful functional catalogs; preserve complete author material locally.
