# papanda — приложение для тайм-менеджмента

[English](README.en.md)

Комплект для создания своего локального приложения по мотивам papanda:
главное дело и замена, задачи, календарь, привычки, занятия, заметки, стикеры,
хронология и счётчики. Описаны как основные возможности, так и небольшие
механики интерфейса и внешний вид.

## Состав комплекта

| Файл | Что в нём |
|---|---|
| [PROMPT.md](PROMPT.md) | Основное задание агенту: 12 разделов, связи, обязательные действия, порядок реализации |
| [SPEC.md](SPEC.md) | Подробное ТЗ: поля данных, поведение разделов, 33 настройки, 24 сценария приёмки |
| [FEATURES.md](FEATURES.md) | Все 64 детали взаимодействия: облачко, двойной пробел, жесты, история отмены, преобразования и другое |
| [VISUAL.md](VISUAL.md) | Оформление: цвета, шрифты, размеры, сетка, карточки, окна и адаптация |
| [reference/design-tokens.json](reference/design-tokens.json) | Точные визуальные значения из стилей papanda |
| [reference/default-layout.json](reference/default-layout.json) | Начальная раскладка виджетов |
| [reference/example-layout.json](reference/example-layout.json) | Раскладка заполненного примера |
| [demo-data.json](demo-data.json) | Связанные вымышленные данные разработчика ИИ для проверки приложения |

## Что понадобится

Компьютер, редактор и ИИ-агент с доступом к файлам и запуску команд.
Для предложенного стека — Python 3.12+ и браузер; зависимости устанавливает агент.
Интернет нужен для работы агента и установки пакетов. Основное приложение
не требует ключей API, Google Calendar, облачного аккаунта или хостинга.
Сам агент может требовать аккаунт и оплату по своим условиям.

## Как собрать

1. Создайте пустую папку проекта. Скопируйте туда весь этот комплект: четыре
   документа задания, папку `reference` и `demo-data.json`.
2. Откройте папку в редакторе, дайте агенту доступ к приложенным файлам и отправьте
   целиком текст `PROMPT.md`.
3. Агент должен прочитать SPEC.md, FEATURES.md, VISUAL.md и пример данных,
   составить план и затем реализовать приложение. Первый этап не завершает всё задание.
4. Запустите приложение указанной агентом командой. Проверьте основной сценарий,
   сохранение после перезапуска и внешний вид по визуальной спецификации.
5. Пройдите 24 сценария из SPEC.md и потребуйте отчёт по всем 64 пунктам FEATURES.md.
   Исправляйте конкретные несоответствия, а не принимайте наличие кнопок за готовность.

Для продолжения работы:

> Сверь реализацию с SPEC.md, FEATURES.md и VISUAL.md. Перечисли пропущенные или
> неполные пункты, затем реализуй их, сохранив работающие функции и данные.
> Проверь поведение и внешний вид, обнови таблицу выполнения всех 64 пунктов.

Если внешний вид отличается:

> Сверь интерфейс с VISUAL.md и reference/design-tokens.json. Исправь цвета,
> типографику, размеры, карточки, сетку и окна; используй соответствующую раскладку.
> Не меняй визуальную систему на свой дизайн. Проверь 390, 768, 1440 и 1920 px.

## Пример данных

`demo-data.json` описывает вымышленного разработчика ИИ и проект «Атлас».
Все персонажи, записи и метрики придуманы. Это не личная база автора и не реальные
результаты исследований. Пример остаётся на русском; документация двуязычная.
Агент адаптирует данные к своей схеме, сохраняя связи и относительные даты.
Начальные записи создаются явной командой в отдельной базе и не подмешиваются
в пользовательские данные.
