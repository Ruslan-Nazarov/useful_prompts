# Свой дашборд времени с ИИ

[English](README.en.md)

Цель — собрать с нуля личное приложение по мотивам Papanda: понимать, что сейчас
главное, планировать день и видеть, на что ушло время.

## Что понадобится

- Компьютер, редактор и ИИ-агент, умеющий создавать файлы и запускать команды.
- Пустая папка проекта с доступом агента к ней.
- Для предлагаемого стека — Python 3.12+ и браузер. Агент создаёт виртуальную среду
  и устанавливает зависимости. Интернет нужен для агента и установки пакетов.
- Скопированные в папку проекта [PROMPT.md](PROMPT.md), [SPEC.md](SPEC.md)
  и [demo-data.json](demo-data.json).

Ключи API, Google Calendar и платный хостинг приложению не нужны. Сам ИИ-агент
может требовать аккаунт и оплату по своим условиям.

## Порядок сборки

1. Откройте пустую папку в редакторе и приложите три файла к разговору с агентом.
2. Отправьте целиком содержимое `PROMPT.md`.
3. Дайте агенту закончить первый этап и запустить приложение. Проверьте его в браузере.
4. Продолжайте по этапам из промпта. При ошибке отправьте текст ошибки и действие,
   которым вы её вызвали. Не вводите настоящие личные данные до проверки сохранения.
5. Пройдите критерии готовности из `SPEC.md`, перезапустите приложение и убедитесь,
   что созданные записи сохранились.

Полезный следующий запрос:

> Продолжи следующий незавершённый этап из SPEC.md. Сначала проверь, что уже
> реализовано. Сохрани работающие функции и данные, внеси изменения, запусти
> подходящие проверки и покажи точную команду запуска.

Если агент остановился на макете:

> Подключи все видимые действия к постоянному хранилищу. Проверь создание,
> изменение и удаление записей через интерфейс, а также сохранение после
> перезапуска. Не объявляй приложение готовым по одному скриншоту.

`demo-data.json` описывает вымышленного разработчика ИИ и его проект «Атлас».
Числа в метриках придуманы для демонстрации интерфейса. Это не результаты
реальных исследований. Агент адаптирует данные к собственной схеме хранения.
Технические имена моделей в файле относятся к исходной Papanda.

## Для автора видео: готовая Papanda с отдельной базой

Этот путь нужен для съёмки существующего приложения; зритель собирает своё по
промпту выше. Нужна локальная папка исходников Papanda и Python с её зависимостями.
Скрипт копирует только код приложения и перечисленные служебные файлы. Личная
база, `.env`, интеграции и шаблоны аналитики не копируются.

Из корня исходной Papanda, PowerShell:

```powershell
.\.venv\Scripts\python.exe -B prompt-library\papanda\demo.py prepare --source .
.\.venv\Scripts\python.exe -B prompt-library\papanda\demo.py check
.\.venv\Scripts\python.exe -B prompt-library\papanda\demo.py run
```

Откройте [демо](http://127.0.0.1:8011/). Если язык не переключился,
выберите русский через меню приложения. Остановка сервера — Ctrl+C.
Порт 8011 отделяет адрес и браузерное хранилище демо от обычного запуска на 8000.
Cookie браузера могут быть общими между портами; для съёмки удобен отдельный профиль.

Когда комплект перенесён в другой репозиторий:

```powershell
# Сначала создать среду и установить requirements.txt из исходников Papanda.
python -B papanda/demo.py prepare --source "D:\путь\к\papanda"
python -B papanda/demo.py check
python -B papanda/demo.py run
```

Каждый `prepare` создаёт новый дубль в `papanda/.demo/runs/` и переключает
`current.json` только после успешного заполнения. Старые дубли остаются.
Сценарные даты привязаны к сегодняшнему дню Asia/Qyzylorda. Для конкретной съёмки:

```powershell
python -B papanda/demo.py prepare --source "D:\путь\к\papanda" --date 2026-10-20
```

Дата задаёт записи, а не часы приложения. Если снимаете в другой день, пересоздайте
демо без `--date`, иначе события перестанут попадать в «Сегодня».
Перед новым `prepare` остановите сервер старого дубля.
`run` никогда не пересоздаёт базу; все действия во время записи сохраняются в ней.
Команды печатают абсолютный путь используемой базы.
