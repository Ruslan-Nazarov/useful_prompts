# Промпт: собери мне личный дашборд времени

[English](PROMPT.en.md)

Ты — разработчик. Создай в текущей пустой папке полностью работающее локальное
однопользовательское приложение для управления временем по приложенному SPEC.md.
Это самостоятельная реализация по мотивам papanda, а не копирование её исходников.
Прочитай SPEC.md и demo-data.json, затем приступай к реализации.

Моя идея: на одном экране видеть главное дело, план дня, задачи, привычки,
быстрые мысли и след прошедших дней. Пользователь — разработчик ИИ, но приложение
должно быть пригодно для любого человека. Русский интерфейс, спокойный современный
дизайн, читаемые карточки и минимум лишних действий.

По умолчанию используй Python 3.12+, FastAPI, Jinja2, SQLite, SQLAlchemy и обычные
CSS/JavaScript. Если окружение требует другого стека, объясни выбор и сохрани
функциональные требования. Зафиксируй фактически проверенные версии зависимостей.
Раздели маршруты, модели, операции с данными, шаблоны и клиентский код.

Работай по этапам:

1. Основа: виртуальная среда, сервер, постоянная база, адаптивный дашборд.
   Реализуй главное дело, задачи по наборам, события на сегодня/завтра и заметки.
   Сразу сделай создание, редактирование и удаление через интерфейс.
2. Добавь привычки, хронологию, счётчики дат и категории заметок. Наполни отдельную
   демобазу связными вымышленными данными из demo-data.json.
3. Добавь связанные стикеры с чек-листами, недельный обзор занятий и календарь
   с повторяющимися событиями. Повторения и исключения проверь отдельно.
4. Доработай поиск, настройки, резервную копию/восстановление и доступность.
   Проверь рабочий сценарий SPEC.md и напиши README с точными командами запуска.

В каждом этапе доводи существующие кнопки до рабочего состояния. Не делай
кликабельные заглушки. Не заявляй, что проверил браузер или тесты, если не запускал их.
Когда браузер недоступен, явно отдели автоматические проверки от ручных.
Не прекращай работу после плана: реализуй, запускай и исправляй обнаруженные ошибки.
Уточняй только действительно блокирующие вопросы, остальные решения принимай сам.

Храни пользовательскую базу в data/db/app.db. Демобаза должна быть отдельной;
обычный запуск не должен очищать или подменять данные. Генератор демо принимает
опорную дату, сохраняет связи между записями и отказывается перезаписывать
существующую базу. Даты на экране обрабатывай согласованно в местном часовом поясе.
Не помещай данные, .env, токены или секреты в Git. Перед миграциями делай бэкап.
Не читай личные файлы, профили браузера или другие базы пользователя для наполнения
демо. Используй только приложенные вымышленные данные и новые вымышленные примеры.

Не подключай облачную авторизацию, нейросетевой API, аналитику и внешние календари:
для основного сценария они не нужны. Запускай сервер на 127.0.0.1.
Пользовательский текст показывай безопасно; HTML и скрипты из записей не исполняй.
Оформление должно работать при недоступности внешних шрифтов.

Главный критерий результата: я открываю приложение, меняю план дня, сохраняю
заметку, закрываю сервер, запускаю снова и вижу свои изменения. Покажи путь к базе,
команду запуска, выполненные проверки и оставшиеся ограничения.
