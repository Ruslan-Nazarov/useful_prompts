# Требования к своему приложению

[English](SPEC.en.md)

## Идея и границы

Локальное приложение для тайм-менеджмента. Один пользователь, один браузер, одна база SQLite.
Демо на видео иллюстрирует идею; точное повторение внешнего вида papanda не требуется.
Не нужны SaaS, многопользовательские роли, платежи и обязательный нейросетевой API.

## Поведение

| Раздел | Что пользователь делает | Что сохраняется |
|---|---|---|
| Главное дело | Выбирает один текущий результат, дату начала и запасное дело; завершает | Текущие дела и история завершений с датами |
| Задачи | Создаёт наборы проектов, переключает их, меняет порядок и отмечает задачи | Набор, название, состояние, порядок |
| Расписание | Видит сегодня и завтра, открывает месяц, назначает время и цвет | Событие, дата/время, важность, статус, категория |
| Повторения | Создаёт ежедневное/еженедельное событие; меняет или пропускает один экземпляр | Правило, конец серии, исключения, изменённые экземпляры |
| Привычки | Отмечает выполнение сегодня, видит последовательность дней | История отметок по местным календарным датам |
| Занятия | Задаёт набор «Рабочий день», время занятий, связь с задачей; отмечает выполнение | Наборы, расписание дней недели, журнал выполнения |
| Заметки | Пишет заголовок и текст, выбирает категорию, закрепляет, ищет | Текст, даты создания/изменения, категория, закрепление |
| Стикеры | Добавляет мысль или чек-лист; прикрепляет к задаче, событию, заметке или главному делу | Содержимое, цвет, связь, состояние архива |
| Хронология | Записывает итоги дня, читает прошлые записи | Текст и выбранная дата |
| Счётчики | Видит дни до демонстрации и с начала проекта | Дата, подпись и направление отсчёта |
| Настройки | Меняет видимость блоков, сохраняет/восстанавливает резервную копию | Настройки, файл резервной копии |

Различайте задачи (результат), события (встреча в определённое время),
занятия (повторяемая работа), заметки (знания) и хронологию (что произошло).
Связь между ними важнее большого количества карточек.
Вложенные задачи, голосовой ввод и интеграции можно добавить позднее.

## Первый экран

Верхняя строка: название, сегодняшняя дата, главное дело и два счётчика.
Ниже: расписание и задачи, затем занятия/привычки, заметки и стикеры.
Хронология доступна с этого же экрана. На узком экране карточки идут одной колонкой.
Длинный текст не ломает сетку. Цвет дополняется текстовой подписью.
У каждой кнопки понятное имя, у поля подпись; модальные окна закрываются по Escape
и возвращают фокус. Сохранение и ошибки видны пользователю.

## Данные для демонстрации

Вымышленный герой — Алексей, независимый разработчик ИИ. Делает «Атлас»,
помощника по поиску в документах. У него есть клиентское демо, сравнение качества
поиска, обучение, отдых и неидеально выполненные планы.

В `demo-data.json`:

- `anchor_timezone` — часовой пояс опорного дня.
- `tables` — записи по моделям исходной papanda; своя реализация адаптирует их.
- `{"$date": -3}` — дата за три дня до опорного дня.
- `{"$datetime": [2, "14:00"]}` — дата/время через два дня в 14:00.
- Обычные числа `id`, `task_id`, `note_id` и т. п. — стабильные ссылки внутри набора.
- `recurrence_rule` — правило исходной papanda (`daily`, `weekly`); окончание серии задано отдельно.
- У модели Observation время начала занятия хранится во времени `created_at`;
  при адаптации к своей схеме лучше выделить самостоятельное поле начала.

Начальные записи создаются только по явной команде. Не подмешивайте их в личную
базу. Повторный запуск сервера не должен добавлять дубликаты.
Для своей модели привычек используйте журнал отметок; формат исходной papanda
описывает её текущее состояние и не является требованием к архитектуре новой системы.

## Проверка готовности

1. В новой среде выполнить команды из README и открыть приложение.
2. На пустой базе увидеть понятные пустые состояния без ошибок.
3. Создать задачу в наборе «Атлас», изменить название, отметить выполненной,
   переключить набор и вернуться. Состояние и порядок сохраняются.
4. Добавить событие на завтра, найти в календаре и отредактировать время.
5. Создать еженедельную серию, удалить один экземпляр: соседние недели сохраняются.
6. Завершить главное дело: оно есть в истории, дата начала сохранена.
7. Сохранить заметку с кириллицей, переносами строк и текстом `<script>`.
   Переносы сохранены, скрипт не выполняется. Найти заметку по слову «Атлас».
8. Прикрепить стикер к задаче и отметить пункт чек-листа; связь и отметка сохраняются.
9. Отметить привычку сегодня дважды: не получить двойное выполнение за одну дату.
10. Записать вчерашний итог, проверить порядок хронологии и неделю занятий.
11. Перезапустить сервер: изменения остались. Перезапуск демо не сбрасывает их.
12. Сохранить резервную копию, восстановить в отдельную тестовую базу и сравнить
    записи и связи. Некорректный файл не должен портить существующую базу.
13. Пройти основные действия клавиатурой и проверить ширины 390 и 1440 пикселей.
14. Проверить границу дня, конец месяца, високосную дату, пустой ввод и длинный текст.

Автоматические проверки нужны прежде всего для хранения, дат, повторений,
целостности связей и восстановления. Не заменяйте проверку поведения сравнениями
со строками собственного кода.
